Architecture overview

SupplyChainX follows Django MVT architecture with a service layer for analysis and Celery for background execution. The web process never executes uploaded code; all parsing is deterministic and all extraction is constrained.

Upload ZIP→ Validate archive→ Parse manifests→ OSV / NVD→ Graph + SBOM→ Reports

Scan pipeline

  1. ProjectUploadView validates the ZIP structure (size, count, traversal, symlinks, compression ratio) and stores it with a SHA-256 digest.
  2. dispatch_scan queues a Celery task; if Redis is unavailable, a daemon thread executes the same task.
  3. run_scan reads manifests in memory, de-duplicates dependencies and persists ParsedDependency rows.
  4. OSV batch queries run for exact versions. CVE aliases are enriched from NVD when enabled. Optional pip-audit and gitleaks CLIs add second-opinion evidence.
  5. License records, NetworkX graph metrics, risk signals, a CycloneDX 1.5 SBOM and grounded recommendations are generated.
  6. The scan is finalized with risk/health scores and complete source attribution.

Security boundaries

  • Archive entries with absolute paths, .. segments, symlinks or encryption are rejected.
  • XML manifests are parsed with defusedxml; DTD/ENTITY declarations are rejected.
  • External API calls use bounded timeouts and record success/failure in IntelSourceStatus.
  • LLM recommendations are optional and grounded in scan facts; the deterministic rule engine is the default.
